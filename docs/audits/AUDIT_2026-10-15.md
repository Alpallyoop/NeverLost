# NeverLost readiness audit - 2026-10-15

Scope: the whole repository against `.constellation/` (service map, registry 2.14.0, agent policy, shared
invariants, remote-work rules), `docs/canonical/`, `project.contract.json` and the legacy v1 docs
(`docs/SPEC_NeverLost_v1.md`, `PIPELINE_CONTRACTS`, `THREAT_MODEL`).

Service boundary worked inside: NeverLost owns identity-bound signing, signer identity, trust
verification, provenance chains and signature verification contracts. Nothing in this audit changes the
role, ownership, dependency direction or public schemas; new contracts document existing behavior.

## Findings and resolution

| # | Severity | Finding | Resolution |
|---|---|---|---|
| 1 | Critical | The trust "negative" vectors were tautologies. Wrong-principal and namespace cases compared a variable with a hard-coded wrong string; the malformed-shape case wrote a malformed file but re-read the valid bundle, then accepted its own "did not fail" message as a pass. `CANONICAL_STATUS.md` and the threat model claimed coverage that did not exist. | `_RUN_neverlost_vectors_v3.ps1` rewritten: every negative runs the real verifier or `ssh-keygen` on a real fixture and requires the exact failure code. Mutation-checked (disabling the hash check makes the lane fail). |
| 2 | Critical | No trust-bundle verification existed. `pubkey_sha256` was never recomputed (the threat model said it was), principal format and the closed role set were never enforced, and authority start/confirm recorded hashes without validating trust. | `NL-AssertTrustBundleV1` (fail-closed, recomputes every claim) and `verify_trust_bundle_v1.ps1`; start and confirm verify trust, expected principal/namespaces and `allowed_signers` currency before writing any receipt. |
| 3 | Critical | `sign_file_v1.ps1` could never succeed: it passed `-O keyid=` to `ssh-keygen -Y sign`, which OpenSSH rejects. It also did not check that the signer was trusted, and `ssh-keygen` silently keeps an existing `.sig` (prompt answered by EOF, exit 0), so a stale signature could be reported as new. | Rewritten: identity-bound (trusted principal, key id, namespace, and the private key must match the trusted public key), refuses to overwrite, self-verifies before success, records `alg`. |
| 4 | High | Proof lanes wrote test receipts into the live authority ledger and required the operator's session to be inactive. The fixed-time lane produced a replayed session (ledger lines 37-39). | Selftest, CLI vectors, trust vectors, admin selftest and the authority lane run in sandbox copies under `.scratch/sandbox`; private keys are never copied. |
| 5 | High | Nothing ran outside Windows: every runner hard-coded `%WINDIR%\...\powershell.exe`, `ssh-keygen.exe`, `icacls` and `Start-Process -WindowStyle`. Violates the remote-work rule (builds and tests in a Linux cloud session). | `_lib_neverlost_host_v1.ps1` (PowerShell host, ssh-keygen, child processes, sandbox); ACL lane uses `chmod` off Windows; Windows keeps Windows PowerShell 5.1 as the canonical host. |
| 6 | High | Admin plugin receipts were invalid NDJSON (unescaped CR/LF from captured CLI output; 18 of 25 lines). Its selftest was a stub that printed a token. | RFC 8259 escaping; real selftest that parses every receipt line. Historic lines left as written. |
| 7 | High | Tier-0 run receipts were appended with Windows PowerShell `Add-Content` (CRLF, default encoding) into the UTF-8/LF ledger (15 lines). | Appends UTF-8 without BOM with LF. `verify_receipt_ledger_v1.ps1` reports historic CRLF lines. |
| 8 | Medium | Canonical JSON key order used culture-sensitive `Sort-Object` (ICU on Linux, NLS on Windows), so byte order could differ across machines. | Ordinal sorting in every canonical writer and in `allowed_signers` derivation. |
| 9 | Medium | Duplicate `NL-WriteAllowedSignersFromTrust` (the first silently overridden); the active one emitted signer lines without a namespace restriction when a key had none (valid for every namespace). | One writer, derived only from a verified bundle; keys without namespaces are rejected. Output byte-identical to the existing live file. |
| 10 | Medium | Session state written non-atomically. | Temp-file replace plus read-back check before the success token. |
| 11 | Medium | Workbench: tray resolved the repository from the working directory only (installed app showed INACTIVE); action receipts were dropped silently on write failure; `open_path` and the PowerShell host were Windows-only; Linux build failed (no `icon.png`). | Shared root resolution, durable receipts that fail the command on error, cross-platform host and open, `icon.png`; 3 Rust tests (command admission, evidence-root confinement incl. traversal, host override). |
| 12 | Medium | No published contracts or receipt schema for the 13 downstream consumers; registry contract names that NeverLost does not produce. | `docs/contracts/NEVERLOST_CONTRACTS_v1.md`, `schemas/neverlost_receipt_v1.schema.json`, `schemas/neverlost_cli_vector_v1.schema.json`, ledger verifier; drift reported to Constellation (proposal 0003). |
| 13 | Medium | LawVM asked for a published signer list (proposal 0002). | `export_allowed_signers_v1.ps1` (namespace-restricted, product bundle option, receipted). Principal and custody are owner decisions (proposal 0004 C). |
| 14 | Medium | A clean clone could not run any lane (trust material is untracked). | Committed public-only fixture trust root; lanes choose it explicitly with `NEVERLOST_TRUST_SOURCE=fixture` (no silent fallback). |
| 15 | Low | 55 historical patch/backup/diagnostic scripts in `scripts/` (several rewrite the library, assume `C:\dev`, or no longer parse), a broken copy in the repository root, `.bak` files in `src/`. A WatchTower test lived here (reverse dependency). | Moved to `scripts/_archive/` with a README; `.bak` files removed (history keeps them). |
| 16 | Low | `.gitignore` did not exclude private keys; `proofs/keys/*_ed25519` sat untracked one `git add -A` away from a commit. | Private keys, credentials and scratch ignored. No secret was ever tracked (checked `git ls-files`). |
| 17 | Low | Contract Registry writes its shadow profiles into this repository (`runtime/`). | Ignored in Git; reported in proposal 0003. |

## Conflicts between code and canonical documents (reported, not silently chosen)

- `proofs/profiles/*` uses principal `Admin` / role `admin`, outside the SPEC v1 closed role set. Not changed;
  owner decision (proposal 0004 D).
- `project.contract.json` and `docs/canonical/ECOSYSTEM_INTEGRATION.md` list 6 downstream users; the registry
  lists 13. Constellation-managed; not edited here (proposal 0003).
